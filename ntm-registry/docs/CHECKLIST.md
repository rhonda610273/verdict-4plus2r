# 上線前檢查清單

從「有一套程式」到「可以真的開始收 NTM 個案」，中間要做的事。

---

## A. 行政面

- [ ] **知會醫院資訊室 / 資安單位**
  - 在院內電腦上跑伺服器程式，多數醫院需要事先報備或核可
  - 若之後要讓其他電腦連線，要確認防火牆政策與網路分段（VLAN）限制
- [ ] **決定資料保管人**：誰負責備份、誰管帳號、離職時如何交接
- [ ] **與 TB 系統負責人對接**（入口頁與 TB 系統在 `10.100.144.109:3000`）
  - 回報你這台電腦的**院內 IP**（啟動系統時畫面會印出來）、**port**（預設 3001）、
        以及預計開始服務的時間
  - 先確認 NTM 要不要開放給其他電腦連 —— 若維持只有本機，
        入口頁的 NTM 按鈕只有在你這台電腦上點才有效（見 README 第七章）
  - 請對方確認你這台電腦是否需要**固定 IP**（DHCP 換 IP 會讓連結失效）
- [ ] 若日後要把累積的資料拿去做研究發表，那屬於另一件事，
      依院內研究審查程序辦理即可；本系統本身是臨床個管用途

---

## B. 個資保護（本系統存有可識別資訊）

這是臨床個管平台，資料庫裡有姓名、病歷號、電話——個管師要追蹤病人本來就需要這些。
正因為如此，保護措施比去識別化的研究資料庫更重要。

- [ ] **確認誰可以看**：用 `tools/manage_user.py` 幫每位使用者開**個人帳號**，
      不共用；只給實際需要的權限（`viewer` 唯讀／`editor` 可編輯／`admin` 管理員）
- [ ] **人員異動立即停用帳號**：`python3 tools/manage_user.py disable <帳號>`
- [ ] **定期看稽核紀錄**：誰在什麼時間、從哪個 IP、做了什麼，系統都有記錄
- [ ] **匯出的 CSV 也含可識別資訊**：匯出後的檔案跟資料庫一樣要保護，
      不要隨手放桌面或寄到私人信箱
- [ ] **如果之後要拿這些資料做研究分析**：匯出後先移除姓名、病歷號、電話三欄，
      用個案編號取代，再交給統計

---

## C. 電腦本身的安全設定

資料庫的安全上限就是這台電腦的安全上限。

- [ ] **設定開機密碼**，並設定閒置自動鎖定（建議 10 分鐘內）
- [ ] **開啟磁碟加密**
  - Windows：BitLocker（Pro 版以上）
  - macOS：FileVault
  - 沒有加密的話，硬碟被拆走就等於資料全部外流
- [ ] **確認 `data/` 不在任何雲端同步資料夾內**
      （檢查路徑裡有沒有 OneDrive、Google Drive、Dropbox、iCloud）
- [ ] **關閉不必要的遠端桌面 / 遠端協助**
- [ ] 作業系統與防毒軟體保持更新
- [ ] 這台電腦最好**專機專用**，不要拿來收信、上網、下載檔案

---

## D. 系統設定

- [ ] 複製 `config.example.json` 成 `config.json`
- [ ] **開放 Windows 防火牆的 port 3001 輸入連線**，其他電腦才連得到
      （指令見 [`DEPLOYMENT.md`](DEPLOYMENT.md) 第 7 節）
- [ ] 從**另一台電腦**實際連一次確認通得到
- [ ] 決定 `allowed_ips` 要不要收緊成特定幾台電腦
- [ ] 用 `tools/manage_user.py` 建立每位使用者的**個人帳號**（不共用帳號）
      並依實際需要給 `admin` / `editor` / `viewer` 權限
- [ ] 密碼長度至少 12 字，不要用醫院常見的預設密碼
- [ ] 設定開機自動啟動（見 `DEPLOYMENT.md`），避免每次都要記得手動開

---

## E. 備份

- [ ] 決定備份策略，建議 **3-2-1 的院內版**：
  - 本機 `backups/`（每日自動）
  - 加密外接硬碟（每週手動，鎖在辦公室抽屜）
  - 院內核可的檔案伺服器（如果資訊室提供且政策允許）
- [ ] 設定排程自動備份（`DEPLOYMENT.md` 有 Windows 工作排程器與 cron 的作法）
- [ ] **實際做一次還原演練**：把備份檔複製成 `data/ntm.db`，確認打得開、資料在
      —— 沒演練過的備份不算備份
- [ ] 確認備份路徑同樣不在雲端同步資料夾內

---

## F. 資料品質

- [ ] **先建 3～5 筆測試個案**，把整個流程走一遍，確認欄位夠用、選項符合科內習慣
- [ ] **既有 Excel 資料先用 `--dry-run` 試跑**，把報告出來的值一個個確認過再 `--commit`
      （尤其菌種欄位：`MAC`、`M. abscessus` 這類寫法需要人工判斷到底是哪一種）
- [ ] 檢查 `fields.py` 的選項是否要調整（例如貴院常見菌種、慣用處方）
- [ ] **寫一份一頁的填寫規範**，定義模糊的欄位怎麼填。至少要講清楚：
  - 「確診日期」用哪一天（第一次符合三條件的日期？還是決定治療的日期？）
  - 「培養轉陰」的定義（本系統採：連續 ≥3 次培養陰性，以第一次陰性日期為準）
  - 復發 vs. 再感染怎麼判定
- [ ] 若多人共同輸入，找 5 筆做**雙人重複輸入**比對，看一致性如何
- [ ] 匯出 CSV 丟進 Excel / R 看一次，確認格式符合後續統計需求

---

## G. 開始收案之後

- [ ] 每月檢查一次備份有沒有正常產生
- [ ] 每季看一次稽核紀錄，確認沒有異常存取
- [ ] 人員異動時立即 `disable` 舊帳號
- [ ] 個案結案後依院內規定保存，不再需要時安全銷毀

## 常見問題

**Q：可以放到院內伺服器讓大家用嗎？**
可以，但那就變成「院內網站」而非單機系統，資安要求完全不同（需要 HTTPS、
更嚴謹的權限控管、資訊室納管）。請先跟資訊室談，不要自己架。

**Q：可以用 Excel 就好嗎？**
小規模可以，但 Excel 沒有稽核紀錄、沒有權限控管、容易被整份複製帶走，
而且多人同時編輯會撞檔。

**Q：資料可以帶回家看嗎？**
匯出的 CSV 含姓名與病歷號，跟資料庫本身一樣敏感。要帶出請先移除可識別欄位，
或依院內個資規定辦理。不要直接複製 `ntm.db`。
