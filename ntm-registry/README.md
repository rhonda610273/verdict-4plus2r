# 非結核分枝桿菌（NTM）管理系統

非結核分枝桿菌（Nontuberculous Mycobacteria, NTM）**個案管理與追蹤平台**。

**設計前提：個案資料只存在這台電腦，不上任何雲端；系統完全離線可用，
不需要網際網路。**

視覺風格比照院內「結核病防治整合系統（TB）」的設計語言（深藍主色 + 橘色 NTM 識別色、
側邊欄版面、相同的元件命名），可與 TB 系統一起掛在「核而為一」入口頁下並列運作。
兩套系統各自獨立，資料不互通。

---

## 一、三分鐘先跑起來看看

**不需要安裝任何套件**，整套只用 Python 標準函式庫。只需要 Python 3.8 以上。

```
Windows：  雙擊 start.bat
Mac/Linux：./start.sh
```

**不確定電腦有沒有 Python？直接雙擊 start.bat 就好。**
它會實際執行一次來驗證（Windows 10/11 內建一個只會打開 Microsoft Store 的
假 python.exe，光看「找不找得到」會被騙）。真的沒有的話，畫面會停住並印出
安裝步驟，不會一閃就關掉。

第一次啟動會請你建立管理員帳號，然後開瀏覽器輸入：

```
http://127.0.0.1:3001/
```

要停止：在視窗裡按 `Ctrl + C`。

## 二、連線範圍與存取控制

**目前設定：開放院內網路連線**（比照 TB 系統的做法）。啟動時畫面會印出
其他電腦該用的網址，例如 `http://10.100.144.xx:3001/`。

資料本身仍然只存在這台電腦的 `data/ntm.db`，不經過任何雲端服務。

### 還在保護什麼

| 機制 | 說明 |
|---|---|
| 帳號密碼 | PBKDF2 雜湊、登入失敗 5 次鎖定 5 分鐘、Session 12 小時逾時 |
| 三種角色 | `admin` 管理員／`editor` 編輯／`viewer` 唯讀 |
| 稽核紀錄 | 誰、什麼時間、從哪個 IP、做了什麼，全部留存 |
| IP 白名單 | `allowed_ips` 可限定允許連線的電腦，不在名單內一律回 403 |
| Host 檢查 | 擋 DNS rebinding 攻擊 |
| 嚴格 CSP | 頁面不會、也不能對外連任何網站；沒有 CDN、沒有字型伺服器、沒有分析工具 |

> 開發規格書寫「本階段不需要實作登入功能」。本系統**不採用這一點** ——
> 一旦開放區網連線又沒有登入，等於科內任何一台電腦打開瀏覽器就能看到全部個案資料。
> 登入機制已經做好，維持啟用。

### ⚠ 開放區網連線必須知道的兩件事

1. **連線是 HTTP 明文。**密碼與個案資料在院內網路上是可以被側錄的。
   要長期跨電腦使用，請請資訊室協助架設 HTTPS，或改走 VPN。
2. **Windows 防火牆預設會擋**，需手動開放 port 3001 的輸入連線，
   其他電腦才連得到（指令見 [`docs/DEPLOYMENT.md`](docs/DEPLOYMENT.md)）。

### 想收緊成只有特定幾台電腦

改 `config.json` 的 `allowed_ips`，把 `"*"` 換成明確清單：

```json
"allowed_ips": ["127.0.0.1", "::1", "10.100.144.50", "10.100.144.51"]
```

### 想改回只有這台電腦

```json
"host": "127.0.0.1",
"allowed_ips": ["127.0.0.1", "::1"]
```

這是最安全的設定，缺點是入口頁的 NTM 按鈕只有在這台電腦上點才有作用。

## 三、資料存在哪裡

```
ntm-registry/data/ntm.db      ← 全部個案資料，就這一個檔
ntm-registry/backups/         ← 備份
```

* 這兩個資料夾都已寫進 `.gitignore`，**不會被 git 追蹤，不會上傳到 GitHub**
* 系統本身沒有任何對外傳輸的程式碼
* 要搬移或封存，複製 `ntm.db` 一個檔就是完整資料庫

### 備份

```
python3 tools/backup.py                    # 備份到 backups/
python3 tools/backup.py --dest D:\NTM備份   # 備份到指定位置
```

備份腳本會擋下明顯的雲端同步資料夾路徑（OneDrive、Google Drive、Dropbox…）。
**請勿把 `data/` 或 `backups/` 放在任何會自動同步到雲端的資料夾裡** —— 這是最常見的外洩途徑。

## 四、帳號管理

三種角色：

* `admin` 管理員 —— 全部權限，可刪除個案、看稽核紀錄
* `editor` 編輯 —— 可新增、修改個案
* `viewer` 唯讀 —— 只能查看與匯出

```
python3 tools/manage_user.py list
python3 tools/manage_user.py add 王醫師 --role editor --name "王小明"
python3 tools/manage_user.py passwd 王醫師
python3 tools/manage_user.py disable 王醫師
```

**每個人用自己的帳號**，不要共用。所有登入、修改、刪除、匯出都會記錄在稽核紀錄裡
（管理員可在網頁上查看），這是個資保護的基本要求。

---

## 五、要改欄位怎麼辦

全部欄位定義集中在 **`fields.py`** 一個檔案。加一個欄位只要在 `FIELDS` 裡加一行：

```python
dict(name="vitamin_d", label="維他命 D 濃度", type="real", group="basic"),
```

重新啟動後，資料庫會自動加上這個欄位、表單會自動長出這個輸入框、CSV 匯出會自動包含它。
**既有資料不會被動到**（只做新增欄位，不會刪除或改名）。

支援的型別：`text`、`textarea`、`int`、`real`、`date`、`bool`、`select`、`multi`（複選）。

欄位內容依 ATS/IDSA/ERS/ESCMID 2020 NTM 肺病治療指引設計，
完整清單見 [`docs/DATA_MODEL.md`](docs/DATA_MODEL.md)。

## 六、目前的功能

**個案追蹤**

* 追蹤清單依**急迫性排序**：逾期最久的排最上面
* 每筆個案顯示追蹤狀態徽章：逾期 N 天／N 天內到期／追蹤中／未排追蹤／已結案
* 個管欄位：收案狀態、最近訪視日、追蹤頻率、下次追蹤日、訪視紀錄
* **下次追蹤日自動帶入**：填了最近訪視日與追蹤頻率就自動往後推，可手動覆蓋
* 儀表板頂端直接列出**逾期未追蹤名單**，點一下就開啟該個案
* 搜尋個案編號、病歷號、姓名、菌種；可依菌種／收案狀態／治療結果篩選

**登錄**

* 個案表單：分十大類（基本、個管追蹤、共病、微生物、影像、診斷、藥敏、治療、追蹤結果、備註）
* **ATS/IDSA 診斷條件即時判定**：勾選臨床／影像／微生物三條件，畫面立刻顯示是否符合
* 自動計算：確診年齡、療程月數
* 匯出 CSV（含 BOM，Excel 開中文不亂碼），可直接餵給 SPSS／R／Stata
* **統計報表**：儀表板按「📄 統計報表」，產生可直接列印／存成 PDF 的 A4 報表 ——
  院所抬頭、製表者與統計條件、收案概況、各項分布（治療組／觀察組兩欄）、
  共病、年齡性別、追蹤時間點；要哪幾段可自己勾。
  每個段落都附長條圖（對照模式是治療組／觀察組並排），可切「圖＋表／只要圖／只要表」。
  同一份資料也能按「⬇ 統計表 CSV」下載，貼進 Word／Excel 自行排版。
  報表只有統計數字，不含任何個案識別資料
* 稽核紀錄：誰在什麼時間從哪個 IP 做了什麼
* 帳號管理：雙擊 `add_user.bat` 就能新增帳號（不必打路徑），權限分唯讀／編輯／管理員；唯讀帳號不能改資料也不能匯出 CSV
* 衛教專區：
  * **NTM 衛教文章**：院內醫療團隊為病友撰寫的 12 篇（來源 `static/education.js`，
    由 `tools/docx_to_education.py` 從院內 Word 檔轉出，不另外編寫內容）
  * **列印衛教文章給病人**：勾選要給這位病友的文章，填姓名與日期，
    可切換標準／大字／特大字級，一篇一張列印或存成 PDF
  * **用藥說明單張**：勾選處方藥，印出服法、可能的副作用、需定期做的檢查與該回診的警訊。
    有勾就只印勾的藥，完全不勾則印全部供手寫打勾。
    ⚠ 內容為系統預設草稿，**待院內衛教組審核**；要增修改 `static/drugsheet.js`
* 軟刪除：刪掉的個案仍留在資料庫，可還原

**統計儀表板**（資料收著收著就自動長出來，不必等到要分析才做）

* 頂端 KPI：收案總數、追蹤中、**逾期未追蹤**、已治療、培養轉陰、轉陰率
* **確診趨勢**：可切換年／季／月；期數少時用直條比大小，期數多時用折線看走勢
* **菌種分布**、**影像型態**、**治療結果**、**共病盛行率**：橫向長條，附數值
* **年齡性別金字塔**：依確診年齡分層，男女左右對照
* **藥物敏感性分布**：每個藥物的 S / I / R 堆疊比例與受測數
* **治療組 vs 觀察組分組呈現**：預設就是兩組並排對照（菌種、影像型態、性別、共病…），
  也可以切成只看其中一組。兩組人數不同時，切「組內占比 %」用各自的分母換算，
  才不會被長度誤導
* 篩選列（起始年、結束年、菌種、族群）**一次套用到所有圖表**，數字永遠互相吻合
* 每張圖都有「表」的切換，數值不會只存在於圖上
* 滑鼠移到任何一根長條或資料點都會顯示明細，鍵盤 Tab 也讀得到同樣內容

圖表是自己畫的 inline SVG，沒有引用任何圖表函式庫，離線一樣正常顯示。
配色經過色盲模擬驗證（男/女兩色在三種色覺缺陷下的分離度 ΔE 24.7，門檻為 8）。

### 視覺規範

比照 TB 系統的設計語言，變數命名與元件 class 都沿用同一套，方便日後對照維護：

```css
--navy:#1e3a5f;  --blue:#2c5282;   --blue-mid:#3a6fa8;
--orange:#f97316;  --orange-light:#ffedd5;  --orange-dark:#c2410c;   /* NTM 識別色 */
```

元件：`.sidebar` / `.nav-item` / `.topbar` / `.card` / `.stat-card` / `.data-table`
/ `.btn` / `.badge` / `.panel`。寬度 900px 以下側邊欄改為漢堡選單。

**唯一刻意不同的地方**：字體不連 Google Fonts。規格書建議用 CDN 載入 Noto Sans TC，
但那需要連外網；本系統必須離線可用，所以改用系統內建的繁中無襯線字體
（`Noto Sans TC` → `PingFang TC` → `Microsoft JhengHei`），視覺上幾乎一致，
而且拔掉網路線照樣正常顯示。

### 把既有的 Excel 資料匯進來

已經累積在 Excel 或 CSV 裡的個案，不需要重打。**匯入工具在你自己的電腦上執行，
資料全程不離開本機。**

```
rem 1. 看看檔案有哪些欄位，並產生對應表
python tools\import_data.py --file 我們的資料.xlsx --inspect

rem 2. 用記事本打開 import_mapping.json 檢查對應，不要匯入的欄位設成 null

rem 3. 先試跑，看有沒有讀不懂的值（不會寫入任何東西）
python tools\import_data.py --file 我們的資料.xlsx --dry-run

rem 4. 確認沒問題再真的匯入
python tools\import_data.py --file 我們的資料.xlsx --commit
```

會自動處理的狀況：

* **民國年**：`114/1/5`、`民國45年3月2日`、`1140315` 都會轉成西元
* 各種日期寫法：`2025/03/01`、`2025-03-01`、`20250301`
* 性別：`M`／`F`／`男`／`女`／`1`／`2`
* 是否欄位：`Y`／`N`／`有`／`無`／`V`／`✓`／`1`／`0`
* CSV 的編碼：UTF-8、UTF-8 BOM、Big5 都讀得懂
* 沒有個案編號時自動編號

**看不懂的值不會亂猜**，會在試跑時全部列出來讓你確認。像 `MAC` 這種同時符合
多個選項的菌種寫法，會原樣保留並提醒你手動確認，不會自作主張選一個更精確的。

個案編號重複時預設**略過**；要覆蓋既有資料加 `--update`。

### 想先看看圖表長什麼樣？

還沒有個案的時候儀表板是空的。可以先灌一批示範資料：

```
python3 tools/demo_data.py --yes        # 產生 60 筆示範個案
python3 tools/demo_data.py --clear      # 看完清乾淨
```

示範個案編號一律以 `DEMO-` 開頭，跟真實個案一眼可分，資料是亂數生成的，不對應任何真人。

## 七、上線前一定要做的事

見 [`docs/CHECKLIST.md`](docs/CHECKLIST.md)。最關鍵的三件：

1. **開機密碼 + 磁碟加密**。本系統存有姓名、病歷號、電話等可識別資訊，
   電腦本身的安全就是資料庫的安全；硬碟沒加密就被拆走，等於資料全部外流
2. **每個人用自己的帳號**，不要共用；所有存取都會留下稽核紀錄
3. **定期備份並實際做一次還原演練** —— 沒演練過的備份不算備份

### 「核而為一」入口連結

TB 系統負責人提供的主機是 **`10.100.144.109:3000`**，入口頁與 TB 系統都在上面。
這兩個連結已經填進 `config.json`，側邊欄的「返回核而為一入口」與衛教專區頁的
相關連結會自動套用：

```json
"portal_url": "http://10.100.144.109:3000/index.html",
"tb_url":     "http://10.100.144.109:3000/TB主系統整合.html"
```

要改位址只要動 `config.json`，不必改程式。若入口頁其實不在 TB 那台主機上，
把 `portal_url` 改成實際位址即可。

> 注意：`10.100.144.109` 是**院內私有位址**，只有連上醫院網路才連得到，
> 而且對方主機要開著。從家裡或手機網路開這個網址一定失敗，這是正常的。

### 入口頁的 NTM 按鈕

入口頁在同事的主機上，同仁是從自己的電腦點那顆 NTM 按鈕，按鈕會連到
**你這台電腦的 IP:3001**。目前系統已開放院內網路連線，所以按鈕對科內同仁有效
（前提是防火牆已開放、你的電腦開著）。

要回報給 TB 系統負責人的三件事：

1. **你這台電腦的院內 IP** —— 啟動系統時畫面會直接印出來，標註「回報這個」
2. **port** —— 3001
3. **預計開始服務的時間**

另外請對方或資訊室確認：你這台電腦是否需要設**固定 IP**。
若是 DHCP 動態配發，IP 一換入口頁的連結就失效了。

## 八、檔案結構

```
ntm-registry/
├── server.py              HTTP 伺服器（純標準函式庫）
├── database.py            SQLite 資料層
├── fields.py              ★ 欄位定義，要改欄位改這裡
├── config.example.json    設定檔範本（複製成 config.json）
├── start.bat / start.sh   啟動腳本（會自行偵測 Python）
├── help_no_python.txt     啟動腳本用的說明文字
├── help_failed.txt        啟動失敗時的排除指引
├── static/                前端（index.html / app.js / charts.js / style.css）
├── tools/
│   ├── backup.py          備份
│   ├── manage_user.py     帳號管理
│   ├── import_data.py     把既有 Excel/CSV 匯入（在本機執行）
│   ├── xlsx_reader.py     免安裝套件的 .xlsx 讀取器
│   ├── demo_data.py       產生示範個案（看圖表用）
│   └── gen_datadict.py    由 fields.py 產生資料字典
├── data/                  ← 資料庫（不進版控）
└── backups/               ← 備份（不進版控）
```
